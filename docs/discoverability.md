# Helping people find Codex Bridge

Recommendations reviewed on 28 September 2026. Documentation improvements help
people understand the project; they do not guarantee search rankings or indexing.

## What the repository now provides

The README describes the product in searchable, ordinary language: OpenAI Codex
inside Home Assistant, ChatGPT sign-in, project chats, scheduled tasks and MCP
home control. It links feature guides through a [documentation index](README.md)
and answers installation and always-on usage questions. Competitor comparisons
live on their own page so the README stays focused on Bridge.

## Useful next steps

1. **Use a clear repository description.** Suggested wording: “OpenAI Codex in
   Home Assistant: ChatGPT sign-in, project chats, files, scheduled tasks, Assist
   and optional MCP home control.” The repository already has relevant topics;
   review their relevance instead of repeating keywords in the README.
2. **Publish a small public documentation site.** Use a stable URL, a descriptive
   title and summary for each page, and ordinary links between installation,
   features and guides. Keep the repository as the source of the documentation
   so the site does not become a second stale copy. Add the site to the GitHub
   About section once it exists. This is a proposed publishing step, not a site
   that has already been created.
3. **Help search engines find the site.** Once hosted, provide a sitemap and
   canonical URLs and verify the site in Search Console. A small well-linked
   site can be discovered without a sitemap, and submission does not guarantee
   indexing. Files in this repository do not control crawling of github.com.
4. **Add real product screenshots.** Show a project chat, scheduled-task editor
   and Home Assistant tools setup, with readable captions and alternative text.
   Use a clean demonstration environment without private chats or credentials.
5. **Build relevant links when ready.** Installation guides, release notes and
   genuinely useful community posts give people routes to the project. A HACS
   default-catalogue submission would be a separate decision; the earlier
   discovery enhancement was closed as not planned and is not reopened here.

GitHub explains how [repository topics help discovery](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/classifying-your-repository-with-topics).
Google's [SEO starter guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)
and [sitemap guide](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview)
cover the public-site basics.

## AI search

Keep feature descriptions accurate, readable and available as public text.
Google's [AI optimisation guidance](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)
says special AI files such as `llms.txt` are not required and are ignored by
Google Search. They are not a substitute for useful pages and crawlable links.
Other services have their own policies; no single file guarantees inclusion.
